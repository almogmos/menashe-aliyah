# לוח העלייה, מבצע כנפי שחר

דף אחד לצוות העלייה של פרויקט בני מנשה, נובמבר 2026, מ-11.11 ועד הטיסה האחרונה ב-26.11.
ארבעה אזורים: עמוד ראשי, לוח זמנים, עולים (כולל טבלת השליטה) וטקסים.

## מה יש בדף ומה אין

- הכל נלקח ממערכת הניהול המלאה של הפרויקט, רק החלק של העלייה מ-11.11.
- ראיונות, תקציב ומסמכים לא נכנסים לדף.
- העולים מופיעים כמספרים, ובנוסף ברשימת עולים עם שם מלא, 4 הספרות האחרונות של הדרכון ושיוך לטיסה.
  אין תאריכי לידה, מספרי דרכון מלאים, מספרי תיקים או הערות חופשיות.
- רשימת העולים נבנית מקובץ הטיסות: `python3 scripts/import_flights.py <קובץ.xlsx> _db "<תיאור המקור>"`, ואחריה `build.py`.
- טיסות הפנים: לכל עולה גם קבוצה וטיסת פנים (או "כבר בדלהי"), לפי עמודת "הערות הסעים" בקובץ ותכנית טיסות הפנים
  מהמערכת המלאה (`_db/ticketing/domestic.json`, המסמך `ticketing/domestic`). השיבוץ בין שתי טיסות של אותו יום
  מחושב באותו כלל כמו במערכת המלאה. בדף אין מחירים, חשבוניות או הערות חופשיות של טיסות הפנים.
- מספרי הזמנה של כרטיסים מוסרים מההערות.

## איך הדף מתעדכן

המערכת המלאה שומרת תמונת מצב (לו"ז, צוות ותחומי אחריות, קבלות פנים ואישורים, בלי רשומות עולים) כקובץ JSON
באחסון הקבצים שלה, בכל פעם שהבעלים פותח אותה ומשהו השתנה. המסמך `public/snapshot` מצביע על הקובץ האחרון.
משימה מתוזמנת בודקת את המצביע, ואם הוא חדש מורידה את הקובץ, מפצלת אותו ומריצה את הבנייה:

```
python3 scripts/split_snapshot.py <snapshot.json> _db
python3 scripts/build.py _db
```

רשימת העולים מתעדכנת רק מקובץ טיסות שמועלה ידנית (`scripts/import_flights.py`).

```
python3 scripts/build.py <תיקיית הנתונים>
```

תיקיית הנתונים כוללת את המסמכים מהמערכת המלאה: `gantt/main.json`, `welcomes/main.json`, `visa/main.json`
ו-`ticketing/{meta,assign,p1..p6}.json`. היא לעולם לא נכנסת לריפו (ראו `.gitignore`).

## קבצים

- `index.html`: הדף עצמו, עם הנתונים בפנים.
- `data.json`: אותם נתונים, לצורך בדיקה ומעקב שינויים.
- `scripts/build.py`: בונה את שני הקבצים מהמערכת המלאה.
- `scripts/template.html`: העיצוב והקוד של הדף.
- `scripts/assets.html`: הלוגואים.
